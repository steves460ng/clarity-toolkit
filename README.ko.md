# Clarity Toolkit

[English README](README.md)

아이디어를 구체화하고, 필요한 질문을 만들고, 복잡한 설명을 이해하고, 다음 작업자에게 맥락을 전달하는 ChatGPT용 스킬 모음입니다.

## GitHub에서 플러그인 추가하기

저장소 접근 도구와 플러그인 제작·등록 도구가 제공되는 ChatGPT 환경에서는 이 저장소의 주소를 주고 비공개 플러그인으로 추가해 달라고 요청할 수 있습니다. 이는 패키징과 계정 등록을 도구로 처리하는 방식이며, 모든 ChatGPT에서 GitHub 주소만으로 바로 설치되는 기능은 아닙니다. 사용 가능 여부는 계정, 워크스페이스 정책과 연결된 도구에 따라 달라집니다.

### 1. 플러그인 추가 요청하기

필요한 도구가 제공되는 대화에 다음 요청을 붙여 넣으세요.

> https://github.com/steves460ng/clarity-toolkit  
> 이 저장소의 `clarity-toolkit/` 폴더를 검토하고, 내 ChatGPT 계정에 비공개 플러그인으로 추가해 줘. 같은 플러그인이 이미 있으면 중복 생성하지 말고 저장소 버전과 비교해 줘. MIT 라이선스와 원본 출처를 보존해 줘. 등록 후 플러그인 링크와 5개 스킬 중 등록된 스킬을 알려 주고, 확인한 결과와 아직 검증하지 못한 사항을 구분해 줘.

설치할 플러그인 소스는 `clarity-toolkit/` 폴더에 있습니다. 저장소 루트에는 개발 도구도 있으므로 저장소 전체를 그대로 플러그인으로 패키징하지 않습니다.

### 2. 등록된 플러그인 선택하기

응답으로 받은 플러그인 링크를 열고, 사용하는 환경의 안내에 따라 활성화하거나 선택하세요. 새 플러그인을 사용하려면 새 대화가 필요한 환경도 있습니다.

계정에 등록됐다는 것만으로 스킬 호출 성공까지 확인된 것은 아닙니다. 대화에서 플러그인을 사용할 수 있게 되면 다음처럼 짧게 요청해 보세요.

> @Clarity Toolkit grill-me로 교육 교안에 대한 인터뷰를 진행해 줘. 한 번에 하나씩 질문해 줘.

### 3. 기존 플러그인 재사용 또는 업데이트하기

Clarity Toolkit을 이미 추가했다면 다시 등록하지 말고 기존 플러그인을 사용하세요. 업데이트를 요청할 때는 이 저장소 주소와 기존 플러그인을 함께 알려 주세요.

이 저장소에서 플러그인을 추가했다고 해서 GitHub 변경 사항이 자동으로 동기화되는 것은 아닙니다. 이후 저장소 변경을 반영하려면 별도 업데이트가 필요할 수 있습니다.

필요한 도구가 없는 ChatGPT 환경에서는 주소만으로 설치할 수 없습니다. 계정에서 지원하는 플러그인 가져오기 절차를 사용하거나, 플러그인 제작·등록 도구가 제공되는 환경에서 진행해야 합니다.

0.3.0에서는 기존 `grilling` 절차를 `grill-me`에 통합했습니다. 요구사항 인터뷰와 결정의 선후 관계 검토 모두 `grill-me`를 사용하세요. 별도 `grilling` 항목은 제거됩니다.

## 사용 방법

플러그인을 사용할 수 있는 ChatGPT 환경에서 Clarity Toolkit을 선택하고, 원하는 작업을 자연어로 요청하세요. 아래 예시는 요청 문구이며, 별도의 슬래시 명령 입력을 전제로 하지 않습니다.

| 스킬 | 이런 상황에 사용하세요 |
| --- | --- |
| `meta-conv-filter` | 수정 흔적과 대화 의존성을 없애 독립적인 결과물을 만들 때 |
| `grill-me` | 아이디어는 있지만 요구사항을 구체적으로 정하지 못했을 때 |
| `to-questionnaire` | 다른 사람에게 확인할 내용을 질문지로 정리할 때 |
| `wait-what` | 앞선 설명이 어렵거나 맥락을 놓쳤을 때 |
| `handoff` | 대화를 다른 사람이나 새 세션으로 이어가야 할 때 |

### 질문과 초안 직접 수정하기

인터뷰 질문과 결과물은 편집 가능한 글쓰기 블록으로 제공하도록 요청합니다. 질문을 고치거나, 선택지 예시를 고르거나, 자신의 생각을 추가하고 앞선 답변을 바꿀 수 있습니다. 추천안을 먼저 받아들이게 하는 방식 대신 열린 탐색부터 시작합니다. 양식을 채우지 않고 말로 답하거나, 질문을 건너뛰거나, 결정을 보류해도 됩니다.

예를 들어 다음처럼 요청하세요.

> 글쓰기 블록에 열린 질문을 한 번에 하나씩 해 줘. 답변란은 비워 두고, 선택지가 도움이 된다면 예시로만 보여 줘. 내 답을 직접 쓸 수 있게 하고 아직 해결책은 추천하지 마.

초안은 다음처럼 수정할 수 있습니다.

> 수업 시간 20분은 유지하고 대상을 8세로 바꿔 줘. Q2는 열린 질문으로 고치고 나머지 답변은 보존해 줘.

기본 편집 기능의 제공 여부는 사용하는 환경에 따릅니다. 네이티브 글쓰기 블록을 사용할 수 없으면 복사해 수정할 수 있는 텍스트 블록 하나를 제공하고, 실제 편집기가 아니라는 점을 알립니다. 이 대체 블록의 체크박스는 클릭 가능한 UI가 아닌 텍스트 표시이며 자동 저장이나 동기화를 뜻하지 않습니다.

### 자연어로 원하는 작업 요청하기

`@`로 플러그인을 선택한 뒤, 매번 스킬 이름을 적지 않고 목표를 설명할 수 있습니다. 모델은 요청의 맥락을 해석해 적합한 절차를 적용할 수 있습니다. 기존 네 워크플로는 명시 요청을 중심으로 사용하며, meta-conv-filter는 독립적인 결과물의 마무리 단계에서도 적용됩니다. 인터뷰나 질문을 통해 생각을 정리해 달라고 요청하면 `grill-me`를 사용할 수 있습니다.

예를 들어 다음처럼 요청할 수 있습니다.

> @Clarity Toolkit 어린이 감기 예방 교육 교안을 만들고 싶어. 생각을 정리하기 위해 설문을 진행해줘.

이 요청은 내 생각을 정리하기 위한 인터뷰이므로 `grill-me`가 적합한 스킬입니다. 교육 대상의 나이, 수업 시간, 학습 목표 등을 먼저 질문하고, 답변에 따라 후속 질문을 이어갈 수 있습니다.

반면 “학부모에게 배포할 설문지를 만들어 줘”는 다른 사람이 답할 문서 작성이므로 `to-questionnaire`에 해당합니다.

의도를 더 명확하게 전달하려면 다음처럼 요청하세요.

> @Clarity Toolkit 어린이 감기 예방 교육 교안을 만들고 싶어. 교안을 작성하기 전에 나에게 한 번에 하나씩 질문하면서 대상, 교육 목표, 활동 구성을 정리해줘.

스킬 선택은 모델의 요청 해석과 사용하는 환경의 플러그인 지원 방식에 따르며, 항상 동일한 경로로 연결된다고 보장되지는 않습니다. 특정 절차를 명확히 지정하려면 “grill-me로 인터뷰해줘”처럼 스킬 이름을 함께 적으세요. 위 예시는 의도한 사용 방식을 설명하며, 설치 환경에서 실제 동작을 검증한 결과는 아닙니다.

## meta-conv-filter - 대화를 보지 않아도 이해할 수 있는 결과물 만들기

메타대화는 수정 흔적, 사용자와 AI의 대화 이력, 그 대화를 봐야만 이해할 수 있는 모든 표현과 내용입니다. 제작 과정의 서두는 제거하고, 대화에 의존하는 지시어와 생략은 확인된 내용으로 다시 씁니다. 기존 네 워크플로의 독립적인 결과물에 마무리 기준으로 적용되며, “meta-conv-filter로 이 문서를 대화 없이 이해할 수 있게 정리해 줘”처럼 직접 요청할 수도 있습니다.

예를 들어 “두 번째 안을 반영한 개선된 계획”은 실제 선택한 방식이 명시된 계획으로 바꿉니다. 정보가 없으면 확인하거나 미정으로 표시하며, 사실·불확실성·출처·작업 상태와 의미 있는 버전 정보는 보존합니다. 변경 이력이나 대화 기록 자체가 요청 대상이면 필요한 맥락과 함께 유지합니다. 진행 중인 인터뷰의 질문 번호와 탐색 안내도 유지합니다. 결과물에는 메타대화를 제거했다는 안내를 덧붙이지 않습니다.

## grill-me — 질문을 통해 요구사항 구체화하기

만들고 싶은 것, 해결하려는 문제, 검토 중인 계획을 설명하고 인터뷰를 요청하세요.

이미 대화에서 정한 내용은 활용하고, 아직 결정하지 못한 부분을 질문합니다. 사용 대상을 정한 뒤 로그인 방식을 검토하는 것처럼 선행 결정부터 확인합니다. 기본적으로 한 라운드에 1~2개 질문을 하며, 답변을 바탕으로 목표, 범위, 제약과 성공 기준을 정리합니다. 앞선 답변을 수정하거나 결정을 보류해도 됩니다. 요약 확인은 구현이나 외부 작업의 실행 승인이 아닙니다.

### 사용 예시

> grill-me로 요구사항 인터뷰를 시작해 줘.  
> 사내 신규 입사자를 위한 온보딩 페이지를 만들고 싶어.  
> 우선 누가 어떤 문제를 겪고 있는지부터 구체화하자.

질문의 속도도 지정할 수 있습니다.

> 한 번에 하나씩 열린 질문을 해 줘. 답변란은 비워 두고, 내 생각을 추가하거나 질문을 고칠 수 있게 해 줘.

중간에 마무리하고 싶다면 다음처럼 요청하세요.

> 질문은 여기까지 하고, 확정된 내용과 아직 정하지 못한 내용을 나눠 정리해 줘.

### 결과물

목표, 주요 사용자, 작업 범위, 확정된 결정, 제약과 미해결 사항을 담은 요구사항 요약을 얻을 수 있습니다.

## to-questionnaire — 다른 사람에게 전달할 질문지 만들기

내가 답을 모르는 내용을 전문가, 협력사, 고객이나 동료에게 확인해야 할 때 사용하세요.

누가 답할 사람인지, 어떤 답을 받아 무엇을 결정하려는지 알려 주면 상대방에게 전달할 수 있는 질문지로 정리합니다. 배경 설명과 질문별 답변란을 포함하며, 중요한 질문부터 배치합니다.

### 사용 예시

> to-questionnaire로 외부 결제 대행사에 전달할 질문지를 만들어 줘.  
> 수신자는 처음 협업하는 기술 담당자야.  
> 정기결제 지원 여부, 연동에 필요한 조건, 정산 주기를 확인해서 도입 가능 여부를 판단하려고 해.

결과물의 언어를 별도로 지정할 수도 있습니다.

> 대화는 한국어로 하되, 전달할 질문지는 영어로 작성해 줘.

### 결과물

목적, 수신 대상, 배경, 답변 방법, 주제별 질문과 답변란이 있는 Markdown 질문지를 얻을 수 있습니다.

이 스킬은 질문지 작성까지 수행합니다. 이메일이나 메신저로 자동 발송하지 않습니다.

## wait-what — 놓친 맥락부터 쉽게 다시 설명하기

직전 설명이 어렵거나 이해되지 않았다면 재설명을 요청하세요.

핵심부터 다시 설명하고, 필요한 배경과 용어를 보충합니다. 도움이 될 때는 구체적인 예시를 사용합니다. 원래 설명에 있던 불확실성이나 주의점도 유지합니다.

### 사용 예시

> wait-what. 방금 설명을 이해하지 못했어.  
> 캐시가 뭔지부터 설명하고, 응답 속도와 어떤 관계가 있는지 예시로 알려 줘.

설명의 수준이나 길이를 지정할 수도 있습니다.

> 개발 경험이 없는 사람도 이해할 수 있게 세 문단으로 다시 설명해 줘.

### 결과물

핵심 요점, 이해에 필요한 배경, 쉬운 용어 설명과 예시를 얻을 수 있습니다.

새 대화처럼 앞선 설명을 볼 수 없는 경우에는 설명할 문장을 먼저 전달해야 합니다.

## handoff — 다음 작업자가 이어갈 수 있게 정리하기

대화가 길어졌거나 다른 사람·에이전트·새 세션으로 작업을 넘겨야 할 때 사용하세요.

현재 대화에서 확인할 수 있는 내용을 바탕으로 목표, 확정된 결정, 완료한 작업, 미해결 사항과 다음 행동을 정리합니다. 제안한 계획과 실제 완료한 작업을 구분하고, 비밀번호나 토큰 같은 민감한 값은 제외합니다.

### 사용 예시

> handoff로 지금까지의 대화를 정리해 줘.  
> 다음 담당자는 질문지 초안을 작성할 예정이야.  
> 확정된 요구사항, 아직 확인하지 못한 사실, 참고 자료와 다음 행동을 포함해 줘.

새 세션에서 사용할 문서도 요청할 수 있습니다.

> 새 대화에 붙여 넣을 인수인계 문서를 만들어 줘.  
> 다음 세션에서는 모바일 화면 설계부터 이어갈 거야.

### 결과물

다음 작업자가 맥락을 이해하고 이어갈 수 있는 Markdown 인수인계 문서를 얻을 수 있습니다.

새 대화로 자동 전달되지는 않습니다. 생성된 문서를 직접 붙여 넣거나 제공해야 합니다.

## 함께 사용하는 예시

1. `grill-me`로 아이디어와 요구사항을 구체화합니다.
2. 외부 확인이 필요한 내용은 `to-questionnaire`로 질문지에 담습니다.
3. 이해하기 어려운 설명은 `wait-what`으로 다시 풀어봅니다.
4. 작업을 넘길 때는 `handoff`로 맥락과 다음 행동을 정리합니다.

## 결과물 형식

질문, 설명, 요약과 인수인계 문서는 기본적으로 편집 가능한 글쓰기 블록으로 제공하도록 요청합니다. 지원하지 않는 환경에서는 한계를 알리고 복사·수정용 텍스트 블록 하나를 제공합니다. 다른 형식을 지정할 수 있으며, 파일 생성 도구가 있으면 최신 초안의 `.md` 파일도 요청할 수 있습니다.

파일 생성, 스킬 선택과 호출 방식은 사용하는 ChatGPT 환경에 따라 달라집니다. 이 플러그인은 별도 MCP 서버나 실행 스크립트를 요구하지 않으며, 영구 저장이나 세션 간 자동 기억을 제공하지 않습니다.
