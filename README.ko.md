# Clarity Toolkit

[English README](README.md)

아이디어를 인터뷰로 구체화하거나 계획을 검증하고, 다른 사람에게 보낼 질문지를 만들고, 다음 작업자에게 맥락을 넘기는 AI 어시스턴트용 스킬 3개입니다.

| 스킬 | 이럴 때 사용 |
| --- | --- |
| `grill-me` | 아이디어나 계획은 있지만 요구사항이 정리되지 않았을 때, 또는 완성된 계획을 검증받고 싶을 때 |
| `to-question` | 전문가, 업체, 고객, 동료가 필요한 사실이나 결정을 알고 있을 때 |
| `handoff` | 다른 사람이나 에이전트, 새 세션이 작업을 이어받거나, 인수인계 문서로 작업을 재개할 때 |

각 스킬은 AI 어시스턴트에게 흔한 습관을 바로잡습니다. 인터뷰보다 바로 작업을 시작하는 습관, 질문지를 만들어 달라는 요청에도 받는 사람이 답할 질문을 사용자에게 되묻는 습관, 제안한 계획과 실제로 끝낸 작업을 섞어 쓰는 습관입니다.

스킬은 일반 Markdown으로 작성되어 특정 모델, 앱, 서비스에 종속되지 않습니다. 편집 가능한 문서처럼 환경에 따라 없을 수 있는 기능을 쓰는 경우, 그 기능이 없을 때의 대안도 함께 적혀 있습니다.

## 설치

각 스킬은 `skills/<이름>/SKILL.md` 파일 하나로 완결됩니다. 파일 머리에 `name`과 `description`이 있고 그 아래에 지침이 이어집니다. 공용 파일, 템플릿, 스크립트는 필요 없습니다.

- **`SKILL.md` 스킬을 불러오는 도구:** 각 `skills/<이름>/` 폴더를 도구의 스킬 디렉터리에 복사하거나 설정에서 스킬로 추가하세요. 위치는 도구의 문서를 확인하세요.
- **스킬을 지원하지 않는 도구:** `SKILL.md` 본문을 사용자 지정 지침, 시스템 프롬프트, 프로젝트 지침에 붙여 넣거나, 대화에 첨부하고 그대로 따르라고 요청하세요.

### 프롬프트로 설치하기

어시스턴트가 GitHub를 읽고 도구에 스킬이나 지침을 추가할 수 있다면, 대화에 다음 요청을 붙여 넣으세요.

> https://github.com/steves460ng/clarity-toolkit
> `skills/` 아래의 SKILL.md 3개를 읽고 이 도구에 스킬로 설치해 줘. 같은 이름의 스킬이 이미 있으면 새로 만들지 말고 업데이트해 줘. 이 도구에서 스킬을 설치할 수 없으면, 각 파일을 어디에 두거나 사용자 지정 지침으로 어떻게 추가하면 되는지 알려 줘. 다른 설정은 바꾸지 마.

## 사용 방법

자연어로 요청하세요. 스킬 이름을 함께 적으면 원하는 절차가 더 확실하게 선택됩니다.

### grill-me — 질문으로 요구사항 구체화하기

> grill-me로 인터뷰해 줘. 사내 신규 입사자를 위한 온보딩 페이지를 만들고 싶어.

기본적으로 채팅에서 1~2개씩 단계별로 묻기 때문에 모바일에서도 읽기 편합니다. 사용 대상처럼 먼저 정해야 할 것부터 묻습니다. 한 번에 많은 질문을 받고 싶으면 "설문 모드로 해 줘"나 "한꺼번에 물어봐"처럼 요청하세요. "설문"이라는 단어만으로는 설문 모드가 되지 않습니다. 그러면 한 차수에 10-15개 질문을 주제별로 묶어 최대 3차까지 진행하고(1차 전체 윤곽, 2차 심화, 3차 빈틈 채우기), 이후에도 추가 차수를 요청할 수 있습니다. 세션에서 편집 가능한 문서를 만들 수 있으면 설문을 문서로 만들어 각 질문 아래에 바로 답을 적을 수 있고, 다음 차수도 같은 문서에 이어 붙입니다. 자유롭게 답하거나 질문 번호로 답하고, 일부만 답하거나 질문을 건너뛰거나 고쳐도 됩니다. 언제든 "여기까지 하고 정리해 줘"라고 요청할 수 있습니다.

짧게 끝내려면 "빠르게"라고 요청하세요. 질문 5개 이내와 반박 2개로 마칩니다. 요약 전에는 계획을 따져 보는 반박 라운드를 거칩니다. 검증되지 않은 가정, 충돌하는 결정, 실패 시나리오, 빠진 이해관계자나 비용을 묻고, 각 지적은 수용, 반박, 보류 중에 고를 수 있습니다. 완성된 계획을 가져와 따져 달라고 하면 탐색 질문은 건너뜁니다. 계획에서 읽어 낸 결정을 먼저 보여 주어 바로잡을 수 있게 한 뒤 반박 라운드를 반복합니다.

**결과물:** 목표, 주요 사용자, 범위, 확정된 결정, 제약, 반박 결과, 미해결 사항을 담은 요약. 완성된 계획이라면 결정을 유지, 수정, 리스크 잔존으로 나눠 보여 줍니다. 요약을 확인하는 것이 구현 승인을 뜻하지는 않습니다.

### to-question — 다른 사람에게 보낼 질문지 만들기

> to-question으로 외부 결제 대행사에 보낼 질문지를 만들어 줘. 수신자는 처음 협업하는 기술 담당자야. 정기결제 지원 여부, 연동 조건, 정산 주기를 확인하려고 해.

사용자가 답할 수 없는 질문을 되묻는 대신 질문지 자체를 작성합니다. 받는 사람이나 목적이 불분명할 때만 짧은 질문을 최대 2개까지 먼저 합니다. 중요한 질문을 앞에 두고 질문마다 빈 답변란을 넣으며, 마감일이나 이름은 지어내지 않습니다. 대화는 한국어로 하고 질문지는 영어로 받는 것처럼 언어를 따로 정할 수도 있습니다.

**결과물:** 목적, 수신 대상, 배경, 답변 방법, 주제별 질문을 담은 질문지. 작성까지만 하고 발송하지는 않습니다.

### handoff — 다음 작업자에게 맥락 넘기기

> handoff로 지금까지의 대화를 정리해 줘. 다음 세션에서는 모바일 화면 설계부터 이어갈 거야.

확정된 결정, 근거가 있는 완료 작업, 제안, 미해결 사항, 다음 행동을 구분해 정리합니다. 비밀번호나 토큰은 `[REDACTED]`로 바꿉니다. 새 대화에 인수인계 문서를 붙여 넣으면, 어시스턴트는 이를 현재 상태의 증거가 아니라 확인할 맥락으로 다룹니다.

**결과물:** 다음 작업자나 새 세션이 이어서 작업할 수 있는 인수인계 문서. 도구에 기억 기능이 없으면 새 대화는 이전 대화를 기억하지 못하므로 문서를 직접 옮겨야 합니다.

## 함께 사용하는 예시

1. `grill-me`로 아이디어를 구체화합니다.
2. 다른 사람의 확인이 필요한 내용은 `to-question`으로 질문지에 담습니다.
3. `handoff`로 맥락과 다음 행동을 넘깁니다.

## 결과물 형식

인터뷰 질문은 대화창에 바로 표시됩니다. 요약, 질문지, 인수인계 문서는 세션이 지원하면 편집 가능한 문서로 만들고, 지원하지 않으면 복사할 수 있는 Markdown 블록 하나로 제공합니다. `.md` 파일은 요청할 때만 만듭니다.
